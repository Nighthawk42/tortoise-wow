# Memory system

## Ownership and scope

Memory belongs to the sidecar, not the MaNGOS gameplay database and not Eluna
Lua globals. The sidecar enforces tenant, persona, actor, visibility, retention,
and deletion policy before an adapter is called.

MemPalace is a candidate adapter. It is not embedded into the core and the wire
contract must not depend on its schemas. A larger knowledge or agent-memory
platform can replace it without changing playerbot code.

## Memory layers

| Layer | Purpose | Typical lifetime |
| --- | --- | --- |
| Working | Current request and a small recent conversation window | Minutes |
| Episodic | Specific interactions that actually occurred | Days to months |
| Semantic | Consolidated facts such as a preference or known name | Until contradicted, expired, or deleted |
| Relationship | Trust/familiarity summaries for one persona and actor/group | Long-lived with decay |
| World lore | Curated, versioned server lore supplied by operators | Deployment/version controlled |

Model output is never automatically a fact. A dialogue candidate becomes
eligible for episodic memory only after the core posts an `emitted` outcome.
Claims made by a player are stored as attributed claims, not objective truth.

## Privacy scopes

Every record has exactly one visibility scope:

- `persona_private`: only this persona may retrieve it;
- `persona_actor`: this persona in conversations with the same opaque actor;
- `group`: a stable, policy-approved group such as a guild identity;
- `public_world`: operator-approved public facts only;
- `operator`: audit/configuration data, never placed in a model prompt.

Whispers default to `persona_actor` with content persistence disabled. Public
channel content is not automatically `public_world`. Account credentials,
network identifiers, session tokens, private messages, real-world personal
data, and GM-only information are never stored as model memory.

## Stable adapter contract

```python
class MemoryProvider(Protocol):
    async def append(self, records: list[MemoryRecord]) -> None: ...
    async def query(self, request: MemoryQuery) -> list[MemoryHit]: ...
    async def consolidate(self, scope: MemoryScope) -> ConsolidationResult: ...
    async def forget(self, request: ForgetRequest) -> ForgetResult: ...
    async def health(self) -> ProviderHealth: ...
```

Required record fields:

```text
memory_id          UUID generated by the sidecar
tenant_id          server/realm isolation key
persona_id         stable YAML persona ID
actor_id           opaque actor ID or null
scope              one privacy scope
kind               episode, attributed_fact, preference, relationship_delta
content            redacted normalized text or structured fact
source_event_id    immutable correlation to an observed event
observed_at        event timestamp
expires_at         retention cutoff or null under explicit policy
confidence         provenance confidence, not model certainty
revision           optimistic concurrency value
```

Adapters must support tenant-scoped deletion and must never broaden a query's
scope. If a backend cannot enforce those requirements, it is not a compatible
provider.

## Retrieval pipeline

1. Build a query from persona, opaque speaker, channel, topic, and current zone.
2. Apply policy to determine eligible scopes and maximum record count.
3. Retrieve candidates with metadata filters before semantic ranking.
4. Remove expired, contradictory, low-confidence, and over-budget records.
5. Rerank for relevance and diversity.
6. Render short, attributed memory statements into the prompt.
7. Record IDs used for audit, without logging their private contents.

Retrieval has a strict latency budget. When it expires, dialogue proceeds with
working context only. The model must not be asked to fabricate missing memories.

## Consolidation and contradiction

Raw episodes should not grow without bound. A background job may consolidate
several episodes into a semantic or relationship summary. It records the source
IDs and preserves attribution.

New evidence does not silently overwrite old evidence. The service can mark a
record superseded, reduce confidence, or retain both contradictory attributed
claims. Operators need an audit trail for consolidation and deletion.

## Retention and deletion

Retention is selected by a named memory profile and may be narrowed by persona
policy or channel policy. Deletion supports:

- a single memory ID;
- all memory for an opaque actor;
- all memory for a persona;
- all memory in a tenant/realm;
- all expired memory before a cutoff.

Deletion must include embeddings, summaries, caches, and adapter-specific
secondary indexes. Backups need a documented expiry policy.

## Reference provider and MemPalace evaluation

Start with a small reference provider that has deterministic integration tests,
for example PostgreSQL plus an optional vector extension, or SQLite for local
development. It establishes expected filtering, deletion, and failure behavior.

Evaluate [MemPalace](https://github.com/MemPalace/mempalace) against the same
contract. Confirm at minimum:

- tenant and persona isolation;
- metadata-first privacy filtering;
- complete deletion behavior;
- bounded query latency and cancellation;
- idempotent ingestion by source event ID;
- export/backup portability;
- behavior when embeddings or the provider are unavailable.

If a broader memory platform is selected later, implement another adapter and
run the shared contract suite. No core changes should be required.
